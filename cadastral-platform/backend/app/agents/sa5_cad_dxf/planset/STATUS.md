# Plan set status (SA5 planset package)

Entry: `build_planset(PlansetInput, out_dir)`; CLI: `python scripts/run_site.py ... --planset` (needs `--acknowledge`).
Sheets: C000 cover/index/locality, C100 existing, C101 proposed, C200 earthworks, C300 stormwater, C310 water/sewer,
C400 driveway plan, C410 long section, C420 driveway layover details, C500 ESC, C600 details; the ref style adds C001 general notes (sheet 2) and keeps C700 as an alias of C001. The legacy A3 style keeps its own twelve sheets.

## Complete for supplied data
Frame/title block (mark, stamp, revisions), C000, C001, C100, C101, C200 (when levels exist), C400, C420, C500 (SA10 layout, indicative), C600 (cited values only).

## Show DATA NOT AVAILABLE panels (by design, nothing invented)
- Existing services / DBYD (C100, C310), water+sewer connection points (C310, rural lots show no connection).
- Stormwater existing assets (C300), pavement thickness / crossing type (C420: "per Council standard drawing, to be confirmed").
- C500 shows "ESCP DATA PENDING" (legacy style) unless SA10 `Sa10Esc` returns output; the ref style runs SA10 through `esc_runner` (see Stage 5). C410 needs levels + driveway; the proposed line needs the platform default end level.

## Known issues not fixed
- (Stage 5) The collision audit is now 0 on every view of the ref run; the legacy A3 style was not re-reviewed.
- Contours stop at the extent of the DEM points; Quia lot uses a locally fetched window DEM only if the network call succeeds.
- Aerial site fetch can fail with HTTP 500 from the NSW service (retried at lower resolution; sheet notes absence).
- DXF viewports use frozen layers; DXF not opened in a real CAD package (ezdxf audit only).
- Text font: Liberation Sans Narrow in the PDF (bundled in ./fonts); DXF style ARIAL NARROW / arialn.ttf.

## Reference style (stage 1)
Foundation plus one finished proof sheet (C101 Proposed site plan, A1) in the style of the engineer's own drawings (reference: JCE-004-CV-1100).
Build: `build_planset(inp, out, style="ref", only=["C101"])`; CLI `--planset-style ref --planset-sheets C101`. Default (`style="legacy"`) is unchanged: 12 A3 sheets, verified identical on the lot2 sample set.
- What exists:
  - `core.py` A1 paper, `Sheet.paper`, Item fields `pattern` / `edge` / `edge_lw` / `hatch_lw`, `View.callout_boxes` / `View.leaders`. PDF page size and DXF layout size follow `Sheet.paper`.
  - `style.py` colour tokens, `Conventions` (graphic conventions measured from the reference, NOT requirements), hatch and AR-CONC stipple (PDF vector dots, DXF AR-CONC hatch), boundary (black plus yellow dash, `JCE_BDY`), kerb, fence, outline helpers, symbols (HYD, T, WM, grate, tree canopy, north point, scale bar). Symbols are drawn only when data exist.
  - `callout.py` boxed UPPERCASE call-outs, leader from the middle of a box edge (landing then diagonal, dot or arrow), greedy placement that avoids earlier boxes, leaders, labels and the title block, `nudge_boxes`.
  - `frame_a1.py` A1 border, A to F / 1 to 8 zone grid, 77 mm title block (DD.MM.YY dates, CV-1xxx drawing number, `JCE-XXX-` placeholder when `PlansetInput.job` / `Proj.job` is empty), datum and not-a-survey notes panel above the title block. CHECKED and APPROVED stay blank. Company data come from `Brand`; ABN only when set.
  - `crossover.py` crossover geometry for any frontage bearing (body, kerb-end wings, kerb and gutter band, kerb lines, width dimension, call-outs). Width and flare come from the SA3 polygon; the kerb is always drawn ASSUMED ("ASSUMED KERB LINE: SURVEY REQUIRED"); the council standard shows "COUNCIL STANDARD DRAWING GOVERNS (NOT SELECTED)" unless SA3 reports a selected standard.
  - `sheets_ref.py` `c101_ref`: boundary with lengths, neighbour lot labels, illustrative dwelling footprint with the proposed hatch, setback dimensions (reuses `draw.building_setbacks`, now with an optional `avoid`), driveway, crossover, assumed kerb and road pavement, services symbols (only if supplied), north point, scale bar, call-outs. FFL only if available and then marked INDICATIVE. Aerial off by default (`RefCtx.aerial`).
  - `tests/test_planset_ref.py` (19 tests: A1 page, title block, call-out geometry, crossover geometry, no driveway, angled frontage, DXF audit and A1 layout, no dashes, legacy unchanged).
- Not done at stage 1 (all since done, see Stage 2 onwards): the other 11 sheets.
  - No contours or spot levels on C101 by design. Existing-building hatch, landscape green and tree canopy are available but not drawn (no data on this sheet).
  - Scale is chosen from STD_SCALES with a 32 mm margin; 1:100 is used only when the lot fits (the lot2 sample needs 1:200).
  - The assumed road pavement is the area beyond the assumed kerb outside cadastral lots (road reserve polygon if the cadastre supplies one). No road width exists in the data, so it runs to the edge of the view.
  - Setback dimensions use the legacy tick style, not the reference dimension style. Call-out placement is greedy; a crowded sheet can still show a leader over linework.
  - DXF checked with ezdxf only (audit 0, A1 layout, AR-CONC and ANSI31 hatches present), not opened in a CAD package. The PDF stipple is generated vector dots, so it differs slightly from the DXF AR-CONC hatch.
  - `job` is a `PlansetInput` field but no CLI flag sets it yet. DRAWN and the DRN column show `drawn_by` (default "JCE", the company code), not personal initials.

## JCESITE branding, AI statement and codes (ref style only; amended)
Single source: `codes.py` (brand constant, AI statement, drawing-number scheme, layer mapping table). Legend: `docs/11-jcesite-layer-and-drawing-codes.md` (generated from `codes.py`).
- Brand: the A1 frame shows a plain text wordmark "JCESITE" (bold) and "AI-ASSISTED SITE PLANNING" from `codes.PlatformBrand` / `PLATFORM_BRAND`. The JCE Brand (logo, company name, tagline, website, ABN, contacts) is never read; ABN and contacts print only if a platform brand setting fills those fields (empty by default). DRAWN shows "JCESITE", DRN column "JCS" (unless `drawn_by` was set to something other than the legacy default "JCE"). PDF author is "JCESITE". Report and other modules are untouched.
- AI statement: "AI GENERATED DRAFT. NOT CHECKED OR CERTIFIED. MUST BE CHECKED AND VERIFIED BY A QUALIFIED PERSON BEFORE ANY USE." is boxed (red edge, bold, upper case) in the title block STATUS cell and at the top of the notes panel on every ref sheet. "PRELIMINARY: NOT FOR CONSTRUCTION" is kept. CHECKED and APPROVED stay blank. New title block field "AI CHECK" (lower left) has a blank tick box and blank checked-by name and date lines.
- Drawing number: `JCS-{job}-CIV-{NNN}` (NNN = digits of the sheet number, empty job shows XXX); replaces JCE-...-CV-1xxx in the ref frame only. Sheet table for C000..C700 is in the docs file.
- Layers: `JCS-{DISC}-{ELEMENT}-{TYPE}` (SITE, ANNO, FRAM, VIEW; LINE, HATCH, TEXT, SYMB, NONE). The ref builders still use the working names; `codes.apply_layer_scheme` renames every item once before rendering (`generate._build_ref`), using `codes.ELEMENTS` (name, colour, lineweight, linetype, description, old names). JCS layers are in `layers_ext.BY_NAME` and `REF_LAYER_NAMES`, so they are registered lazily; a ref DXF holds only JCS layers (plus 0 and Defpoints) and the viewport sits on `JCS-VIEW-VPRT-NONE`. Legacy DXF layers and entities are unchanged.
- Dwelling out: C101 no longer draws the footprint, its hatch, call-out, setback dimensions or the FFL text. Boundary, neighbours, crossover, driveway, assumed kerb, road name, north point, scale bar, grid, notes, boundary lengths and crossover width stay. A labelled panel "SETBACK DIMENSIONS: PLACEHOLDER (BUILDING DESIGN NOT SUPPLIED)" (top left of the view, also added to the sheet notes) stands in for setbacks. The old path is kept behind `PlansetInput.show_dwelling=True` (default False); the call-out and setback code are unchanged.
- Tests: `tests/test_planset_ref.py` now covers brand absence (no JCE INFRASTRUCTURE, jceinfrastructure or ABN), the AI statement in both places, the drawing number scheme and sheet table, JCS layer regex on the DXF, the default dwelling-off with placeholder and the opt-in path; legacy default unchanged.

## Stage 3b (ref style): owner feedback round 2 (supersedes the stage 2 and 3 notes where they differ)
1. DCDB to the viewport edges: `cadwin.py` pads the cadastre fetch from the viewport (rotated rectangle outset 5 percent of its diagonal, not a fixed buffer), clips lot linework to the viewport and labels every visible lot LOT n over DP. Missing lot or plan attributes print DATA NOT AVAILABLE. Live runs: `Sa1Cadastre.window_lots` (new, `geometry.from_mga`) returns lots and road reserves in the window; `scripts/run_site.py` passes it as `PlansetInput.cadastre_fetch` (and the loaded rules as `PlansetInput.rules`). A window the source cannot fill (query failure, record limit, offline fixture) is stated on the sheet as "DCDB ... NOT AVAILABLE ... NOT CHECKED, NOT CLEAR".
2. Scale chooser and rotation: `viewport.py`. 1:100 first; before stepping up it rotates the view so the long axis of the lot lies along the sheet (north point rotated and labelled, note "VIEW ROTATED n DEG ... NORTH POINT SHOWN"). Only if neither fits it steps to 1:200, 1:250 ... and prints "SCALE 1:n CHOSEN: LOT EXTENT EXCEEDS 1:100 VIEWPORT". `View.twist` (anticlockwise degrees) drives the PDF transform and the DXF viewport twist (`view_twist_angle`, DCS view centre, model hatch angle reduced by the twist). Lot 2 now fits at 1:100 rotated 52 degrees clockwise.
3. Spot levels removed from C100 (contours kept). C400 carries at most 8 sparse spot levels near the driveway (`draw.spot_levels_sparse`, clear of reserved boxes).
4. Titles: a separate white strip (33 mm) directly above the title block: bold UPPERCASE title, red underline, "1:100 @ A1    1:200 @ A3" (A3 denominator is the A1 one doubled, computed), graduated scale bar beside it, reason and rotation notes. Used on every drawing sheet including C001, C410 (H and V pairs) and C600.
5. C001 general notes (`lga_notes.py`): grouped headings (general; survey and existing services; earthworks and ESC; driveway and crossover; stormwater and flood; standards and approvals; register), numbered, three balanced columns, one body type size, no orphan headings. Council named from the council source document title in the requirements file (else the lot LGA name + COUNCIL); lines cited from `Cites` and the rules JSON; any topic without a resolved requirement prints "COUNCIL REQUIREMENT: <TOPIC> UNRESOLVED, CONFIRM WITH <COUNCIL> COUNCIL"; the AI-generated and needs-checking statement is always present.
6. Typical details (`sections.py`): cut and fill batters (slope drawn, labelled 1:n or "1:n TBC"), pavement layers (wearing, base, subbase, subgrade with thickness dims), kerb and gutter profile, crossfall, in the reference hatches ("/" existing, "\\" proposed, AR-CONC stipple, bitumen grey). Values come from `Cites` keys (`driveway.pavement.*`, `earthworks.batter.*`, `kerb.*`, `driveway.crossfall_pct`); otherwise "TBC (COUNCIL STANDARD DRAWING GOVERNS, NOT SELECTED)". C600 is a 4 x 2 grid of boxed details; C420 right column has the kerb/layover and pavement sections; C200 section panel is larger with batters. C410 now uses the widest scale that fits (1:20 here) and moves the notes to the top.
- Tests: `tests/test_planset_ref_stage3b.py` (chooser, rotation, DXF viewport twist on real Lot 2, no spot levels on C100, dual scales on every plan sheet, LGA notes from data including an LGA with no knowledge file, batter and pavement labels with a cited and an uncited case, synthetic edge-to-edge cadastre). 78 passed with the earlier planset tests.
- Weak: the offline Lot 2 fixture holds only the 3 adjoining lots, so the DCDB cannot fill the viewport in that run (it says so); the live window query is untested against the real service. DXF viewport twist verified with ezdxf's transformation matrix only, not a CAD package. The typical details occupy about half of each C600 box; geometry is schematic.
